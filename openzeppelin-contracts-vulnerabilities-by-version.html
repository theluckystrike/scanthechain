OpenZeppelin Contracts vulnerabilities by version

By Michael Lip (Mike), independent smart contract security researcher. Data fetched 2026-10-29.

This page lists the 24 GitHub advisory ids for @openzeppelin/contracts and @openzeppelin/contracts-upgradeable, from the 2021 TimelockController advisory to the 2025 lastIndexOf memory-access bug. The two OpenZeppelin repositories published 23 of them. GitHub added GHSA-88g8-f5mf-f5rj. The page counts the advisories per stable npm release, and the lookup shows the advisories for your version.

Support status and upgrade advice

The project's own security policy says, quoting:

Security patches will be released for the latest minor of a given major release. For example, if an issue is found in versions >=4.6.0 and the latest is 4.8.0, the patch will be released only in version 4.8.1.
Only critical severity bug fixes will be backported to past major releases.

Supported lines, quoted from the same policy (5.x gets all security fixes; 4.9 and 3.4 get critical fixes only; 2.5 and versions below 2.0 get none):

If you are on 4.9.x or 3.4.x, the policy promises only critical fixes. Two non-critical fixes still reached 4.9.x after 5.0.0 (released 2023-10-05): 4.9.5 for GHSA-699g-q6qh-q4v8 and 4.9.6 for GHSA-9vx6-7xxf-x967. The policy does not promise more.

The TimelockController critical advisory

One critical TimelockController issue has two ids in the GitHub database: GHSA-fg47-3c2x-m2wr for contracts and GHSA-vrw4-w73r-6mm8 for contracts-upgradeable. In both packages it affects the stable releases 4.0.0 to 4.3.0 and 3.3.0 to 3.4.1. The TimelockController advisory (CVE-2021-39167) says, quoting:

Deployed instances of TimelockController should be replaced with a fixed version by migrating all assets, ownership, and roles.

Replacing a deployed contract is not an npm update. The workaround of the advisory, quoting: "Revoke the executor role from accounts not strictly under the team's control."

The deprecated 4.9.4 release

The 4.9.4 advisory (CVE-2023-49798, duplicated delegatecall in Multicall) says, quoting:

The duplicated delegatecall was removed in 4.9.5. The 4.9.4 version is marked as deprecated.

npm confirms: both @openzeppelin/contracts@4.9.4 and @openzeppelin/contracts-upgradeable@4.9.4 carry an npm deprecation notice. If your lockfile pins 4.9.4, move to 4.9.6. Version 4.9.5 is still in the range of GHSA-9vx6-7xxf-x967.

The 5.0 to 4.9 backport pattern

The Base64 advisory (CVE-2024-27094) patches two branches at once. Its fix line, quoting:

Upgrade to 5.0.2 or 4.9.6.

The policy promises backports to past majors only for critical fixes. This advisory is low in the repository and medium in the GitHub database. This fix was also backported to 4.9.6.

Method and sources

Fetched 2026-10-29 with the GitHub API: the advisories of both repositories (repos/OpenZeppelin/openzeppelin-contracts/security-advisories and repos/OpenZeppelin/openzeppelin-contracts-upgradeable/security-advisories), the global GitHub Advisory Database entries for both packages (advisories?ecosystem=npm&affects=@openzeppelin/contracts and the same query for @openzeppelin/contracts-upgradeable). Also fetched: the npm registry metadata for both packages (versions, dist-tags and deprecation notices), the project's SECURITY.md, and the OSV record of each of the 24 ids (api.osv.dev/v1/vulns/<id>), which gives the CVE aliases in the duplicate section. The lookup and the tables use global-database ranges; where the repository advisory disagrees on severity, the advisory table shows the global rating and names the repository rating next to it. First-patched versions come from the advisory's first_patched_version field. Data fetched 2026-10-29 at 07:30 UTC. A second fetch at 10:33 UTC gave the same ids, severities, ranges, stable versions and npm dist-tags.

Counts in the version table are advisory ids whose published range for @openzeppelin/contracts covers the version, computed from the global database ranges in the fetched files. The major-line table counts issues per package, as its note says. npm also lists 53 pre-releases and solc-0.7 builds of @openzeppelin/contracts and 35 of @openzeppelin/contracts-upgradeable (rc and beta tags, and builds named like 3.4.2-solc-0.7). The tables and the lookup do not count them; only stable npm releases are counted.
