Look up a compiler version

Enter a released version as three numbers, for example 0.8.19. The bug names for a version come from bugs_by_version.json. The details of each bug come from bugs.json. For each listed bug the result shows the name, the severity, the official summary, the introduced and fixed versions, the conditions and the official link.

The lookup needs JavaScript. Without it, use the two tables below.

Source: bugs_by_version.json and bugs.json, fetched 2026-10-11.

A listed bug applies only under its conditions. The list is about the compiler version. It does not say that a contract compiled with that version has the bug.

The two files show four more facts on 2026-10-11.

The docs sentence gives 0.3.0 as the start of the list. The file bugs_by_version.json also holds 11 versions below 0.3.0, from 0.1.0 to 0.2.2. For each of them it lists the entry AncientCompiler. The summary of that entry in bugs.json is "This compiler version is ancient and might contain several undocumented or undiscovered bugs."

The docs page names four severity values. The file bugs.json uses six values. They are high (3 entries), medium/high (4), medium (12), low/medium (3), low (23) and very low (21).

The docs page explains the condition keys optimizer and evmVersion. The file bugs.json also uses the keys ABIEncoderV2, yulOptimizer and viaIR. The docs page does not explain these three keys. This page shows each key and its value as the file has them.

17 of the 66 entries have no introduced value. The file bugs_by_version.json lists each of these 17 entries for 0.1.0, the oldest version in the file. The fixed version is the first version without the bug, so a bug is not listed for its fixed version.

Limits of this page

This page does not test contracts. It shows the entries that the official list names for a compiler version. A compiler version on the list is not proof that a contract has the bug. The docs page describes separate checks "that report whether the smart contract contains the bug or not".

The lookup gives a result only for the 121 versions in the file. For a version that is not in the file it shows a message and no count. Nightly and prerelease builds get no result, because the list does not track them.

The release dates, the counts and the bug data are copies of values in the two files. This page does not show the description and check values of bugs.json. Both files can change after 2026-10-11.

How this page was made

Both files were fetched from raw.githubusercontent.com on 2026-10-11 at the commits named near the top. A script wrote the two tables and the lookup data from the files. No value in these two tables was typed by hand.

A separate check applied one rule to bugs.json. A version has a bug when the entry has no introduced value or the version is at or above introduced, and the version is below fixed. The check compared each version as three whole numbers, so that 0.8.9 is below 0.8.10. For all 121 versions the rule gave the same bug names as bugs_by_version.json.

The data was fetched on 2026-10-11 and can change after that date. This page copies public data. It is not security advice and it is not an audit of any contract.
