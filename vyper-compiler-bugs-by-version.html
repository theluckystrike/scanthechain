COMPILER SECURITY

Vyper compiler bugs by version, lookup and full tables

By Michael Lip (Mike), an independent developer. He runs this site and builds the tools on zovo.one. Data fetched 2026-10-20.

Vyper has published 54 security advisories in the GitHub security advisories of the vyperlang/vyper repository. Each one names the compiler range that it affects. 47 of them give a patched version for each range. 7 of them have at least one range with no patched version as of 2026-10-20. That mapping matters when you verify a deployed contract: Etherscan records the compiler version a contract was built with, and this page tells you which published bugs that build carries. The sibling page covers Solidity compiler bugs by version.

Version lookup

Type a Vyper stable release, for example 0.3.10. You can also paste the Etherscan form, for example vyper:0.3.10. The lookup recomputes the affected advisory set from the embedded data on your device; nothing is sent anywhere.

Severity and the one critical

In the ratings of the vyperlang/vyper repository advisories, exactly one advisory is critical: GHSA-5824-cm3x-3c38 (CVE-2023-39363), "Incorrectly allocated named re-entrancy locks", published 2023-08-05. It affects Vyper 0.2.15 through 0.3.0 and was fixed in the 0.3.1 release. On 30 July 2023 attackers used this bug to drain several Curve.Fi liquidity pools (Vyper post-mortem). The advisory says that a contract is at risk only when a function with a named lock makes an external call before it updates storage, and a second function uses the same key.

Severity source. Every severity label and count on this page, in the lookup and in the tables, is the rating in the vyperlang/vyper repository advisories. Other databases rate many of the same bugs differently. On 2026-10-20 the GitHub Advisory Database (the reviewed records that Dependabot uses) listed 47 of the 54 advisories, rated 3 of them critical (GHSA-5824-cm3x-3c38, GHSA-52xq-j7v9-v4v2 and GHSA-9x7f-gwxq-6f2c), and gave a different rating than the repository for 20 of the 47. NVD shows a CVSS 3.1 base score of 9.8 CRITICAL for CVE-2024-24561 and CVE-2024-24563, which the repository rates high and medium. Check the advisory and the CVE record before you rank the risk of a bug.

Worked example

Etherscan shows the compiler of a verified Vyper contract in the form vyper:0.2.15. Paste that into the lookup. The result for 0.2.15 is 38 known published advisories (repository ratings: 1 critical, 6 high, 15 medium, 16 low), and the critical one is GHSA-5824-cm3x-3c38. The Vyper post-mortem says: "All Vyper contracts that have been compiled with versions v0.2.15, v0.2.16, and v0.3.0 are vulnerable to the malfunctioning re-entrancy guard". A listed advisory does not prove that a contract is exploitable. Read each advisory and check whether the contract uses the affected feature, as the critical example above shows.

Method and limits

The advisory numbers on this page come from the GitHub security advisories of vyperlang/vyper (54 advisories, fetched 2026-10-20; links point to the repository advisory pages, 7 of the 54 are repository-level advisories not mirrored in GitHub’s global advisory database, including one attached to a withdrawn CVE), cross-checked against the PyPI release list (31 stable releases). A version is counted as affected when it falls inside an advisory's published range, so every count can be recomputed from the GitHub and PyPI data linked here.

Limits worth stating honestly. The advisory database lists published, catalogued bugs; it is not a census of every compiler defect. The tables and the lookup show stable releases only. The 0.5.0 pre-releases are in the note above the advisory table. Ranges marked >= 0.3.8 with no upper bound mean "unfixed as of the fetch date". Severity ratings are the repository publisher's, not mine, and other databases rate many advisories differently (see the severity source note). As of 2026-10-20 each stable release, including 0.4.3, is in the range of at least 7 advisories. A count on this page is not a guarantee about a contract.
